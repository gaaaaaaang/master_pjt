## 실행 / 비교

```sh
cd /private/tmp/fab-frontend-adv/apps/web
npm run dev -- --port 5175
npm test
npm run build
```

- 사용자 화면: http://127.0.0.1:5175/
- 차트 예시: http://127.0.0.1:5175/?preview=trend
- 조건 확인: http://127.0.0.1:5175/?preview=clarification
- 데이터 없음: http://127.0.0.1:5175/?preview=unavailable
- 오류: http://127.0.0.1:5175/?preview=error
- 이전 React 평가 대시보드: http://127.0.0.1:5175/trace

Preview는 synthetic 디자인 검토 데이터이며 배너로 표시한다. 실제 채팅/피드백 API를 호출하지 않는다.
개발 서버는 Vite proxy로 기존 localhost:8000 API를 연결한다. `FAB_API_TARGET`으로 proxy 대상 변경 가능.
`VITE_API_BASE`를 사용하면 직접 API URL을 지정한다. 운영 배포는 `/api`와 `/health` reverse proxy 또는 이 환경 변수가 필요하다.
기존 Streamlit `apps/web/app.py`는 변경하지 않았다. 사용자가 첨부한 화면은 Streamlit이며, React 사용자 화면으로의 전환을 제안하는 실험이다.

## 레퍼런스와 적용 판단

2026-09-07에 아래 페이지를 실제 브라우저로 확인했다.

1. [토스 고객센터](https://support.toss.im/): 한 가지 질문과 입력창을 중심으로 한 시작 화면, 간단한 시작점, 넓은 흰 여백.
2. [토스 광고 가이드](https://toss-ads.gitbook.io/guide): 회색 탐색 영역과 흰 본문을 명확하게 분리. 단, GitBook의 디자인도 섞여 있으므로 전체를 토스 고유 시스템으로 해석하지 않는다.
3. [토스 디자인 블로그](https://toss.tech/category/design): 큰 제목, 차분한 보조 텍스트, 경계가 명확한 콘텐츠 묶음.
4. [토스 고객센터 AI 챗봇 사례](https://toss.tech/article/chatbot): 내부 카테고리 탐색보다 자연어 요청을 해결 행동으로 연결하는 원칙. 레퍼런스의 자산이나 로고는 복제하지 않았다.

FAB 적용: 사용자는 답변과 다음 행동을 먼저 본다. 실행 기록은 답변 아래 버튼으로, 에이전트별 반환 데이터는 상세 패널 내 두 번째 펼침으로 제공한다. SQL/계획 JSON을 메인 화면에 기본 노출하지 않는다. 근거와 한계는 숨기지 않고 답변 및 상세에서 확인한다. 연결 상태는 실제 health 요청으로 확인하며 임의로 성공 표시하지 않는다.

## 구현

- 회색 사이드바, 검색 가능한 세션 대화 기록, 신규 대화, 고정 하단 입력창.
- 현황/원인/추이/지식 질문 시작점. 클릭 시 편집 가능한 초안에 입력한다.
- 분석 범위: FAB/라인/공정 drawer. 명시 값의 우선순위와 대화 기억에 대한 안내.
- 결과 우선 답변, 안전한 텍스트 렌더링, 차트/표 전환, CSV 다운로드, 답변 복사, 피드백.
- 에이전트별 접힌 트레이스, 근거 탭, 데이터/SQL 탭, 원본 응답 상세.
- 오류, 중단, 조건 확인, 데이터 없음 상태. 실패 상태를 성공으로 바꾸지 않는다.
- 한글 조합 입력, Shift+Enter, Ctrl/Cmd+K, native dialog 포커스 제어, 방향키 탭 전환, 모바일 숨긴 사이드바 inert.
- SSE 청크/UTF-8/CRLF/끝 버퍼 처리. 중간 끊김을 성공으로 간주하지 않음. 중단/3분 timeout과 요청 중 중복 전송 방지.
- 기존 chart 렌더러 추출. 다중 시리즈 범례에 색상 표시. 미지원 형식/잘못된 값 안내.
- `/trace`로 기존 평가 화면을 보존. 사용자 화면에 평가 suite를 노출하지 않는다.

2. 수정한 모바일 메뉴 포커스 복귀와 Escape, inspector 탭 방향키/닫기, 조건 확인/오류/데이터 없음 시나리오를 UI로 검증.
3. 후속 질문/새 대화/대화 검색/새로고침 지속/다시 시도/수신 중단을 최소한의 mock 또는 브라우저 테스트로 검증. 백엔드 LLM 대량 호출 없이 진행.
4. 긴 차트 축 레이블, null/빈 값, 긴 표와 pagination, 피드백 실패를 검토. 요청한 실제 데이터의 의미를 임의로 바꾸지 않는다.
5. 소스 포맷 정리, README 사용자 화면 실행 설명 추가, 최종 build/test 및 커밋. 이미 통과한 검사는 변경 사유가 있을 때만 반복한다.

## 알려진 제한

- 별도 React 실험이며 기존 Streamlit 사용자 세션은 마이그레이션하지 않는다.
- 대화는 현재 탭의 sessionStorage로 보관한다. 서버 대화 목록 API가 없어서 여러 기기 동기화는 없다.
- Google Fonts Noto Sans KR 사용, 네트워크 미연결 시 시스템 한국어 글꼴 fallback.
- backend 결과 품질, 영어 limitation 중복, 원천 데이터 정확성은 프런트엔드 작업 범위 밖이다.
- 실제 API feedback 저장/CSV 브라우저 다운로드는 아직 E2E 검증 전.
- `/trace`는 기존 코드라 이 실험의 사용자 UX 개선이 적용되지 않는다.

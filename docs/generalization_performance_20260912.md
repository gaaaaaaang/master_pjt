# 공통 실행 경로의 품질·효율 개선

`feat/final_adv`에서 질문별 예외 추가 대신 모든 모델 단계가 사용하는 입력 경로를 개선했다.
사용자가 승인한 `skax.ai-talentlab.com`의 기존 `gpt-4.1`을 사용했으며 모델 변경은 없다.

## 공통 변경

1. **근거 상태 공유**: 조회 성공 여부, 조회 행과 샘플의 범위, 시계열 요약, 문서 출처,
   조건부 계산의 가정, 원인 후보와 추가 확인 사항, 차트의 누락 구간을 코드로 구조화한다.
   답변 생성·사전 검토·최종 검토·실행 복구가 이 정보를 함께 사용한다.
   문서나 사례가 없다는 이유로 조회 가능한 수치까지 없는 것으로 취급하지 않으며,
   공정 간 차이와 시간에 따른 증가, 관측과 원인 후보, 조건부 계산을 구분한다.
2. **손실 없는 입력 압축**: 반복되는 자료는 참조로 공유하고 같은 열을 가진 행은 열 목록과
   값 배열로 전달한다. 숫자를 반올림하거나 문서를 요약·삭제하는 압축이 아니다.
   모델 입력에 이미 있던 모든 값·행 순서·NULL·시각·단위·출처를 복원할 수 있다.
   기존 상위 단계의 근거 샘플링 제한은 그대로 명시된다. 최종 API 응답과 대화 저장 형식은 바꾸지 않는다.
3. **호출별 측정**: 실제 입력·출력 토큰과 호출 시간에 더해 입력 형식과 바이트 수를 기록한다.
   이 통계에 질문 원문, 문서 본문, API 키는 저장하지 않는다. 기존 모델 검토 단계와 SQL 검증은 유지한다.
4. **고정 평가**: 새 8문항과 FAB·공정·지표·차트·검토 승인 조건을 구현 전에 고정했다.
   FAB10~13, 여러 지표, 같은 공정 후속 질문, FAB·공정 변경, 추세, 비교, 진단, 영향도,
   문서 지식을 포함한다. 수정 전후 각 한 번의 전체 실행을 비교하며 실패 문항도 분모에서 빼지 않는다.
5. **실행 지표 경계**: LLM이 추출한 자유 문구를 그대로 조회 지표로 넘기지 않는다.
   기존 지표·동의어 카탈로그로 정규화하고, 등록되지 않은 추론 값은 실행용 지표에 바인딩하지 않는다.
   원래 사용자 질문은 그대로 남아 메타데이터 기반 탐색에 전달된다. 명시적으로 파싱한 지표는
   LLM 제안보다 우선하며, 이 처리는 FAB이나 질문 문구와 관계없이 적용된다.

질문별 문자열이나 FAB별 값을 새 공통 모듈에 하드코딩하지 않았다.
작은 입력 또는 인코딩 표식과 충돌하는 자료는 일반 JSON으로 전달한다.
압축 이득 계산에는 모델에 추가하는 인코딩 설명의 길이도 포함한다.

## 검증 범위

- 수치·FAB·공정·행 순서를 바꾼 입력, 결측값/0/false, 서로 다른 출처의 같은 값,
  불균일한 행, 인코딩 표식 충돌, 실제 HTTP 클라이언트의 입력 및 통계 기록을 검증했다.
- 기존 응답 13개 및 별도 평가 8개의 복합 문맥을 원형 그대로 복원했다.
  기존 13개 복합 문맥은 495,661바이트에서 309,343바이트로 줄었다.
  이 수치는 로컬 재구성 입력의 크기이며 실제 모델 토큰 수와 구분한다.
- 백엔드 전체 시험과 관련 Ruff 검사를 수행했다. 최종 개수는 아래 결과에 기록한다.
  프런트엔드 코드는 이번 변경 대상이 아니다.
- 실제 모델 비교는 `baseline.json`과 `after.json`에 최초 실행 그대로 보존한다.
  응답 시간은 이 소규모 실행의 관측치이며 부하 시험이나 통계적 성능 보장이 아니다.
  전후 SQL 결과 행의 일치는 회귀 검증이며 별도 정답 DB를 이용한 정확도 증명과 구분한다.

## 최종 전후 비교

| 측정 | 수정 전 | 최종 전체 실행 |
|---|---:|---:|
| 조회·지표·차트·모델 검토의 자동 조건 통과 | 7/8 | 8/8 |
| 입력 토큰 | 264,332 | 219,521 |
| 출력 토큰 | 12,482 | 12,311 |
| 응답 시간 중앙값 | 18.457초 | 16.445초 |
| 전체 응답 시간 합계(시험 간 대기 제외) | 164.485초 | 146.640초 |
| 모델 호출 | 51 | 51 |
| HTTP 429 | 0 | 0 |

입력 토큰은 16.95%, 응답 시간 중앙값은 10.9% 감소했다.
전체 질문의 SQL 결과 행은 수정 전과 동일했다. 모델 검토 호출을 생략해서 얻은 절감이 아니다.
최종 백엔드 시험은 **931개 통과**, 관련 Ruff 및 변경 공백 검사도 통과했다.

자동 검사 통과는 모든 문장의 정확도나 표현 품질을 뜻하지 않는다. 수동 검토에서
진단 답변이 7일의 관측 창에 걸친 8개 날짜 집계를 “최신 8일”로 설명하고 긴 소수점을
그대로 노출하는 문제가 남았다. 진단·영향 답변에 반복되는 생성 데이터 출처 문구도
일부 남아 있다. 이번의 계측 가능한 개선은 공통 지표 바인딩과 입력 효율이며,
기간·단위에 따른 문장 표현은 공통 출력 계약의 후속 품질 과제로 구분한다.


첫 수정 후 실행(`after.json`)은 7/8로 기준선 7/8과 통과 개수는 같았지만,
진단 문항이 새로 실패하여 품질 회귀 판정이었다. 입력 토큰은 12.0% 줄었으나 이 결과만으로
개선을 완료했다고 판단하지 않았다. 모델이 추출한 자유 문구가 실행용 지표로 들어가면
스냅샷 조회 대신 다른 데이터 경로로 빠지는 공통 경계 문제를 확인하고 위 5번을 추가했다.
최종 전체 재시험은 `final.json`에 별도 보존한다. 따라서 최종 실행은 이미 관측한 회귀 세트의
재검증이며, 새로운 미관측 질문에 대한 일반화 정확도 수치로 해석하지 않는다.

## 재현

저장소 루트에서 다음 순서로 실행한다. 서로 다른 모델 시험을 동시에 실행하지 않는다.
25초 간격은 이번 비교의 동일 조건이며 서비스 전체에 강제한 대기 시간이 아니다.
원래 기준선은 덮어쓰지 말고 새 파일 이름을 사용한다.

```sh
PYTHONPATH=apps/assistant/src:apps/assistant/scripts .venv/bin/python apps/assistant/scripts/evaluate_fab_followup_live.py --live --fixture apps/assistant/tests/fixtures/generalization_holdout.json --pause 25 --output /tmp/generalization_new.json
.venv/bin/python apps/assistant/scripts/compare_generalization_runs.py --fixture apps/assistant/tests/fixtures/generalization_holdout.json --before apps/assistant/output/evals/generalization_20260912/baseline.json --after /tmp/generalization_new.json --output /tmp/generalization_comparison.json
```

비교기는 질문 파일 해시, 전체 문항 수와 순서, 실행 완료 여부를 검사한다.
호출 단계별 토큰·시간, 최초 통과 수, 쿼리 행 변화, 429 응답을 함께 보고한다.
실패를 수정했다면 다음 전체 실행은 별도 라운드로 보존하며 이전 성공 사례와 합산하지 않는다.
이번 질문 세트는 이후 회귀 세트로 사용하고, 다음 일반화 평가는 새로운 별도 세트로 진행한다.

공통 구현은 `agents/evidence_contract.py`, `agents/context_encoding.py`,
`agents/llm.py`, `agents/usage.py`에 있으며, 원본 자료와 모델 답변은
`apps/assistant/output/evals/generalization_20260912/`에 보존한다.

## 1. 분석 한계 설명

원래 질문은 “방금거는 왜 근거를 분석하지 못한거야?”다. 그대로 넣으면 이전 대화가 없는 새 질문에
의미가 불분명하다. 또 원문은 성공한 데이터 조회가 있음에도 “모든 진단 근거가 불충분”하다고
표현한다. 관측값을 설명하는 근거와 원인을 확정하는 근거를 나누는 편이 좋다.

관련 검색에서 문서가 반환되지 않았다는 것만으로 문서가 존재하지 않는다고 단정하면 안 된다.
실제 조회와 검색 결과를 확인한 뒤 그 결과가 질문에 포함된 독립 예시로 편집한다.

- 질문 초안: [diagnosis-question.txt](feedback_review_drafts/diagnosis-question.txt)
- 답변 초안: [diagnosis-answer.txt](feedback_review_drafts/diagnosis-answer.txt)

## 2. 가동률 영향 계산

원문에 적힌 75.42% → 70.42%, 기준 5 LOT에 비례 모델을 적용하면 감소율은 약 6.63%,
변화 후 처리량은 약 4.67 LOT다. **산술 관계는 맞지만**, 이 검산만으로 원래 DB의 기준값,
관측 기간, 비례 가정의 현실 적용성을 검증한 것은 아니다.

초안은 내부 FAB 이름과 과거 조회 시점을 제거하고, 질문에 명시한 가정값 80%·100 LOT/시간으로
계산 구조를 보여준다. 5%p 하락과 5% 상대 하락을 혼동하지 않고, 75/80을 적용한다.

- 질문 초안: [impact-question.txt](feedback_review_drafts/impact-question.txt)
- 답변 초안: [impact-answer.txt](feedback_review_drafts/impact-answer.txt)

## 3. 기간 추세 설명

원문의 `cmb`와 `cmp` 표기를 확인해야 한다. 전체 수율 범위의 하한은 96.01%라고 적었지만
아래 CMP 시작값은 96.00%로 적혀 있어 표현이 서로 맞지 않는다. 또 표시된 반올림 값의 차이와
본문의 %p 변화가 일부 다르므로 원본 정밀도에서 계산한 값을 확인한 뒤 일관되게 표시해야 한다.
이 문서만으로 어떤 원본 수치가 맞는지 결정하지 않는다.

초안은 실제 숫자를 복제하지 않고, 질문에 명시된 시작값·종료값·중간 하락만으로 설명한다.
시작 대비 종료가 높아졌다는 사실과 매일 계속 상승했다는 주장을 구분하는 예시다.

## 검토 후 적용

[운영 방법](feedback_few_shot.md)의 `inspect`로 원본과 근거를 먼저 확인한다.
초안 파일을 검토·수정하고 `approve`의 질문/답변 파일 인자로 사용한다. 이 세 과거 답변은 상세
evidence가 저장되지 않은 기록이므로 `--source-review-note`에 실제 확인한 근거와 가정값으로
편집한 이유를 적어야 한다. 근거를 확인하지 않았다면 계속 검토 대기로 둔다.

현재 검색은 query type과 질문 유사도를 함께 사용한다. 독립 예시로 질문을 크게 바꾸면
원래 짧은 후속 질문과 유사도가 낮아질 수 있다. 새 질문에 예시가 선택되지 않는 것을 강제로
우회하거나 관련 없는 예시를 넣지 않는다. 승인 후에도 답변의 사실·수치·인용은 현재 근거가 결정한다.

### 프로젝트 명

AI 기반 FAB 이슈 대응 채팅 어시스턴트

### 배경 및 문제 정의

* 현재 상황 (As-Is):

  * 현장 담당자가 이상 징후를 인지한 이후에도, 원인 파악을 위해서는 백오피스(엔지니어링/스케줄링 부서 등)에 별도로 문의하고 데이터 조회를 요청해야 하며, 회신을 받기까지 상당한 시간이 소요됨

  * 원인 분석은 담당자가 SQL을 짜거나 문서를 뒤져가며 수작업으로 진행되어, 질문 하나당 처리 시간과 결과 품질이 담당자 역량에 크게 좌우됨.

  * 단순 수치 조회와 복합적인 원인 추론 문제 구분 없이 같은 방식(수작업 조회+판단+답변 생성)으로 처리되고 있어 비효율이 큼

* Pain Point:

  * 시간: 질문 → 데이터 조회 → 해석 → 답변까지 리드타임이 길어, 특히 복합적인 원인 질의일수록 지연이 커짐

  * 비용: 반복적인 데이터 조회에 SQL 역량 보유자의 리소스가 소모됨

  * 품질: 원인 추론의 깊이와 정확도가 담당자 개인 경험치에 의존해 편차가 큼

* 기회 요인:

  * 질문 유형에 따라 적절한 tool과 agent를 조합하면, 단순 조회는 즉시 처리하고 복합 추론은 표준화된 방식으로 대응할 수 있다.

  * 복합 질의는 사람이 일일이 생각하던 과정을 `Planner -> Supervisor -> specialist tool/agent \`으로 분리해 자동화할 수 있다.

  * Text2SQL과 RAG, 영향도 계산, 유사사례 검색, 그래프 생성, self-reflection 검증을 결합하면 응답 품질을 일정 수준 이상으로 유지할 수 있다.

### 목표 사용자 (Target User)

* **FAB 운영/생산관리 담당자**

* **현장 인력** (WIP·공정 이상 여부를 조회하고, 그 원인과 대응 방안까지 자연어로 질의하는 현장 인력)

### 프로젝트 목표

* 정성적 목표

  * **목표 1**: 질의 응답 자동/표준화 - 단순 현황 조회부터 원인 진단, 영향도 판단, 대응 추천까지 질문 유형에 맞는 툴 조합으로 자동 처리. 백오피스 문의 없이 담당자가 직접 답을 얻을 수 있는 체계를 구축

  * **목표 2**: 복합 추론 품질 확보 - 복합 질의는 planner가 실행 계획을 수립하고, supervisor가 이를 기반으로 tool/agent를 호출한 뒤 결과를 검증 및 정제하여 일관된 답변을 제공

  * **목표 3**: 분석 결과의 가시화 - 추세, 비교, 영향 범위는 그래프 생성 tool 을 통해 시각적으로 제시해 의사결정 속도를 높임

* 정량적 목표 (KPI)

|               |           |                                                 |           |
| ------------- | --------- | ----------------------------------------------- | --------- |
| **성과 지표**     | **목표 수치** | **측정 방법**                                       | **현재 수준** |
| 단순 조회형 질의 정확도 | 75% 이상    | 질문 유형 1,6에 대해 생성 sql 결과와 정답 일치 여부 확인            | -         |

| 질의 라우팅 정확도    | 90% 이상    | 유형 분류기가 7개 질의 유형을 올바르게 판별하는 비율                  | -         |
| 응답 속도         | 평균 5분 이내  | 질문 입력 최종 답변 생성까지 걸린 시간 측정                       | -         |

|          |                               |                            |
| -------- | ----------------------------- | -------------------------- |
| 유형       | 예시 질문                         | 필요 tool                    |
| 현재 상태 조회 | "지금 M2라인 WIP 몇 개야?"           | Text2SQL                   |
| 공정지식 질의  | "Cycle Time Degradation이 뭐야?" | RAG (공정문서)                 |
| 원인 진단형   | "왜 A라인 Queue Time이 늘었어?"      | Text2SQL + RAG             |
| 영향도 질의   | "이 공정 지연이 이번주 수율에 얼마나 영향을 줘?" | 영향도 계산 tool + 영향도 해석 agent |
| 대응 추천 질의 | "B이슈 상황 발생했는데, 어떻게 대응해야 해?"   | RAG(이슈 상황 대응 데이터)          |
| 추세/비교 질의 | "지난주 대비 a제품 수율 어때??"          | Text2SQL + 시각화 tool        |
| 후속/맥락 질의 | "그 중에 제일 심한 애만 보여줘"           | 대화 히스토리 + 상위 tool 재호출      |
| 답변 생성    | -                             | 답변 생성 agent                |

* 공통 구성 요소

  * Planner - 복잡 질의를 해결하기 위해 실행 계획을 수립하고 질문을 해결 순서에 따라 여러 하위 task로 구조화

  * Supervisor - planner가 만든 게획을 바탕으로 적절한 tool/agent 호출. 답변 품질을 점검하고 부족하면 재호출하거나 계획을 수정

* Text2SQL agent— 대화 히스토리·SQL 히스토리 참조

* RAG tool — 공정지식 문서(SMT2020 스펙 기반) / 대응 매뉴얼 분리 검색

* 영향도 계산 tool/agent - 딜레이로 발생하는 손실 수치는 tool을 이용해 계산하고, 수치에 대한 분석은 agent가 판단

* 유사사례 검색 tool

* 답변 생성 agent

* 사용자 피드백 반영 tool — 👍 답변의 질문·SQL을 Few-shot으로 재사용

* self-reflection 검증 — 유형 3·4·5(복합 추론형)에 한해 근거-결론 정합성 재검토

### 기대 효과

* **업무 효율화**: 질의 유형에 따라 즉시 응답, 백오피스 문의 사이클 제거

* **품질 향상**: 복합 추론형 질의 적절성 70%이상 달성으로 원인 진단/대응 추천의 일관성 확보

* **비용 절감**: 질의 즉시 응답으로 백오피스 문의·회신을 기다리며 이슈가 방치되던 시간이 단축되어, 이에 따른 생산 손실(수율 저하, 납기 지연 등) 기회비용 완화

* **설명 가능성 강화** : SQL, 문서 근거, 영향 범위, 시각화 결과를 함께 제시할 수 있다

### 범위 및 제약사항

* In Scope:

  * 7개 질의 유형에 대한 end-to-end 처리

  * 질문 라우터, Text2SQL, RAG, 영향도 계산, 유사 사례 검색, 피드백 반영, self-reflection 검증 agent tool

  * SMT2020 데이터셋 기반

    * 프로젝트에 유관한 부분만 골라서 사용(*105개 tool group, 913~1314대 장비..*)

  * 채팅 인터페이서 UI(근거 SQL/문서 노출 포함)

* Out of Scope:

  * 설비/공정에 대한 AI의 직접 제어 및 자동 실행

  * 상시 실시간 모니터링, 자동 이상 탐지

  * 신규 데이터 소스 통합

  * 텍스트 이외의 입력

  * 시나리오 외 추가 이상 유형 확장

* 제약사항:

  * 프로젝트 기간 8주 내 완료를 전제로 기능 범위 설계

  * 데이터 소스는 MySQL FAB DB로 한정

  * 데이터는 SMT2020 스펙 기반 합성 데이터로 한정

  * 담당자 검토 단계가 필수이므로 완전 자동화된 의사결정·실행은 지원하지 않음

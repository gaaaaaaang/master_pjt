# FAB AI Assistant 핵심 사용자 시나리오

## 데이터 목록

- 기본 공정 데이터 = SMT2020
- 반도체 기본 지식 = 반도체 공정 이론 교육 자료
- 반도체 공정 이론 자료는 문서 추출 후 RAG용 지식 베이스로 구성한다.
- 상황별 대처 = 사용자 시나리오 기반 대응 흐름

## SC-001 현재 상태 조회 시나리오

- `ID` = SC-001
- `상황` = 사용자가 특정 라인이나 공정의 현재 상태를 빠르게 확인해야 할 때
- `예시` = "지금 A라인에 WIP 몇 개야?"
- `목표` = 원하는 라인/공정의 현재 현황을 정확하게 조회

### 사전 조건

- 생산 데이터가 DB에 적재되어 있어야 한다.
- 사용자는 조회 대상 라인명이나 공정명을 입력할 수 있어야 한다.

### 상세 흐름

| 단계 | 사용자 행동 | 시스템 동작 | 비고 |
| - | - | - | - |
| 1 | "지금 M10 A라인 WIP 몇 개야?" 질문 입력 | FAB, 라인, 공정, 지표 등 메타 정보를 식별한다. | 자연어 입력 |
| 2 | 질의를 Planner가 분류 | 답변에 필요한 세부 task를 나누고 실행 계획을 세운다. | 세부 task 계획 |
| 3 | Supervisor가 현재 상태 조회로 판단 | Planner 결과를 보고 적합한 sub-agent를 선택한다. 정보가 부족하면 재질문한다. | 분기 판단 |
| 4 | Text2SQL sub-agent가 SQL 생성 | WIP, Queue Time, 처리량 등 현재 상태 조회 SQL을 생성한다. | 쿼리 생성 |
| 5 | DB 조회 실행 | read-only executor가 SQL을 검증하고 결과를 반환한다. | 데이터 조회 |
| 6 | Composer가 최종 응답 생성 | SQL 결과를 바탕으로 사용자가 이해할 수 있는 자연어 답변을 만든다. | 답변 생성 |
| 7 | Supervisor/Reflection 검증 | 사용자 의도, 기준 시각, 수치 근거가 맞는지 확인한다. | 검증 단계 |
| 8 | 사용자 피드백 수집 | 질문, sub-agent 결과, 최종 답변, 사용자 피드백을 개선 데이터로 저장한다. | 셀프 검증 단계 |

### 입력 예시

```text
지금 M2라인 WIP 몇 개야?
```

### 기대 출력

```text
M2라인의 현재 WIP는 128개입니다.
기준 시각: 2026-08-24 14:10 KST
```

### 성공 기준

- Planner가 사용자 질의를 보고 알맞은 세부 task를 계획한다.
- Supervisor가 Planner 결과를 보고 적절한 sub-agent를 판단한다.
- sub-agent가 근거 기반의 적절한 답변을 생성한다.

## SC-002 원인 진단형 시나리오

- `ID` = SC-002
- `상황` = 사용자가 특정 라인/공정의 지표가 왜 나빠졌는지 원인을 확인해야 할 때
- `예시` = "왜 A라인 Queue Time이 늘었어?"
- `목표` = 실제 공정 데이터와 공정 기본 지식을 활용해 지표 악화 원인을 설명한다.

### 사전 조건

- 공정 데이터가 DB에 적재되어 있어야 한다.
- 공정 문서, 운영 기준, 반도체 공정 지식 문서가 Vector DB에 적재되어 있어야 한다.
- 사용자는 답변에 필요한 FAB, 라인명, 공정명, 기간 등 메타 정보를 제공해야 한다.

### 상세 흐름

| 단계 | 사용자 행동 | 시스템 동작 | 비고 |
| - | - | - | - |
| 1 | "왜 A라인 Queue Time이 늘었어?" 질문 입력 | FAB, 라인, 공정, 지표 등 메타 정보를 식별한다. | 자연어 입력 |
| 2 | Planner가 질의 분류 | 원인 진단에 필요한 세부 task를 계획한다. | 세부 task 계획 |
| 3 | Supervisor가 원인 진단으로 판단 | Text2SQL, RAG, CaseSearch 등 필요한 sub-agent 조합을 선택한다. | 분기 판단 |
| 4 | Text2SQL sub-agent가 SQL 생성 | 최근 추이, 전일/전주 비교, 이상 발생 시점, 관련 공정별 수치를 조회한다. | 쿼리 생성 |
| 5 | RAG sub-agent가 공정 지식 검색 | Queue Time 증가, WIP 증가, 병목, 다운타임 관련 문서를 검색한다. | 지식 검색 |
| 6 | SQL 결과와 RAG 결과 결합 | DB 수치 변화와 공정 지식 기반 원인 후보를 함께 정리한다. | 조합 단계 |
| 7 | Composer가 최종 응답 생성 | 가능한 원인, 영향 지점, 추가 확인 포인트를 자연어로 정리한다. | 답변 생성 |
| 8 | Supervisor/Reflection 검증 | DB 근거와 문서 근거가 모두 반영되었는지 확인한다. | 검증 단계 |
| 9 | 사용자 피드백 수집 | 피드백을 self-reflection 및 개선 데이터로 활용한다. | 셀프 검증 단계 |

### 입력 예시

```text
왜 A라인 Queue Time이 늘었어?
```

### 기대 출력

```text
A라인의 Queue Time 증가는 최근 3일간 특정 공정 앞 대기 건수가 증가한 것과 연관됩니다.

DB 확인 결과:
- 전일 대비 Queue Time: 18% 증가
- 동일 시간대 WIP: 12% 증가
- 병목 공정: A2 공정

공정 문서 기반 확인 결과:
- Queue Time 증가는 병목 공정의 처리량 저하 시 자주 발생
- 상류 공정 투입량 증가 시 대기 적체가 발생할 수 있음
- 설비 다운타임이나 작업자 교대 이력도 영향 요인으로 확인됨

가능한 원인:
1. A2 공정의 처리 속도 저하
2. 상류 공정 투입 증가로 인한 대기 적체
3. 설비 가동률 변동 또는 작업자 교대 영향

추가 확인 포인트:
- A2 공정의 설비 다운타임
- 작업자 교대 이력
- 직전 공정 투입량 변화
```

### 성공 기준

- Planner가 사용자 질의를 보고 알맞은 세부 task를 계획한다.
- Supervisor가 Planner 결과를 보고 적절한 sub-agent 조합을 판단한다.
- sub-agent가 수치 근거와 문서 근거를 결합해 답변한다.

## SC-003 영향도 질의 시나리오

- `ID` = SC-003
- `상황` = 사용자가 특정 공정 지연, 설비 이슈, 수율 변화 등이 전체 생산 지표에 얼마나 영향을 주는지 확인해야 할 때
- `예시` = "이 공정 지연이 이번주 수율에 얼마나 영향을 줘?"
- `목표` = 특정 이벤트나 공정 변화가 수율, 리드타임, WIP 등 핵심 지표에 미치는 영향을 수치로 계산하고 해석한다.

### 사전 조건

- 생산 데이터가 DB에 적재되어 있어야 한다.
- 영향도 계산에 필요한 기준 지표, 비교 기간, 대상 공정/라인 정보가 식별 가능해야 한다.
- 영향도 계산 결과를 해석할 수 있는 기준 문구 또는 해석 규칙이 준비되어 있어야 한다.

### 상세 흐름

| 단계 | 사용자 행동 | 시스템 동작 | 비고 |
| - | - | - | - |
| 1 | "이 공정 지연이 이번주 수율에 얼마나 영향을 줘?" 질문 입력 | FAB, 공정, 영향 대상 지표, 기간을 식별한다. | 자연어 입력 |
| 2 | Planner가 질의 분류 | 영향도 분석에 필요한 세부 task를 계획한다. | 세부 task 계획 |
| 3 | Supervisor가 영향도 질의로 판단 | 필요한 sub-agent 조합과 재질문 필요 여부를 결정한다. | 분기 판단 |
| 4 | Impact sub-agent가 수치 계산 | 공정 현황 데이터를 기반으로 영향도 수치를 계산한다. | 수치 계산 |
| 5 | 해석 agent가 계산 결과 해석 | 계산 수치를 사용자에게 이해 가능한 표현으로 변환한다. | 수치 기반 해석 |
| 6 | Supervisor/Reflection 검증 | 계산식, 기준값, 해석 문장이 질문 의도와 맞는지 검증한다. | 검증 단계 |
| 7 | 사용자 피드백 수집 | 피드백을 self-reflection 및 개선 데이터로 활용한다. | 셀프 검증 단계 |

### 입력 예시

```text
이 공정 지연이 이번주 수율에 얼마나 영향을 줘?
```

### 기대 출력

```text
이번주 해당 공정 지연으로 인해 수율은 약 1.8%p 하락한 것으로 추정됩니다.

확인된 영향:
- 기준 대비 불량 증가 기여도: 62%
- 지연 공정 관련 재작업 증가: 14%
- 최종 수율 손실 추정치: 1.8%p

해석:
- 지연이 발생한 시점 이후 불량률과 재작업률이 함께 상승했습니다.
- 영향은 주로 해당 공정의 처리 지연과 후속 공정 적체에서 발생한 것으로 보입니다.

추가 확인 포인트:
- 지연 발생 시점의 설비 가동률
- 해당 공정의 투입량 변화
- 후속 공정 대기 시간 변화
```

### 성공 기준

- Planner가 사용자 질의를 보고 알맞은 세부 task를 계획한다.
- Supervisor가 Planner 결과를 보고 적절한 sub-agent를 판단한다.
- sub-agent가 계산 근거와 한계를 포함해 답변한다.

## SC-004 추세/비교 질의 시나리오

- `ID` = SC-004
- `상황` = 사용자가 특정 제품, 공정, 라인의 추세 변화나 기간 간 비교를 확인해야 할 때
- `예시` = "지난주 대비 A제품 수율 어때?"
- `목표` = 기간별 지표 차이와 추세를 조회하고, 필요한 경우 시각화 결과를 함께 제공한다.

### 사전 조건

- 생산 데이터가 DB에 적재되어 있어야 한다.
- 기준 기간, 비교 기간, 대상 제품/공정/라인, 지표명이 식별 가능해야 한다.
- Visualization sub-agent가 조회 결과를 차트, 그래프, 표로 표현할 수 있어야 한다.

### 상세 흐름

| 단계 | 사용자 행동 | 시스템 동작 | 비고 |
| - | - | - | - |
| 1 | "지난주 대비 A제품 수율 어때?" 질문 입력 | FAB, 제품, 지표, 비교 기간을 식별한다. | 자연어 입력 |
| 2 | Planner가 질의 분류 | 추세/비교에 필요한 세부 task를 계획한다. | 세부 task 계획 |
| 3 | Supervisor가 추세/비교 질의로 판단 | 필요한 sub-agent 조합과 재질문 필요 여부를 결정한다. | 분기 판단 |
| 4 | DB에서 기준/비교 대상 데이터 조회 | 수율, 불량률, WIP 등 필요한 수치를 기간별로 반환한다. | 데이터 조회 |
| 5 | Visualization sub-agent가 결과 시각화 | 그래프, 추세선, 비교표 등으로 변환한다. | 시각화 |
| 6 | Supervisor/Reflection 검증 | 질문 의도에 맞는 지표와 비교 방식이 반영되었는지 검토한다. | 검증 단계 |
| 7 | 사용자 피드백 수집 | 피드백을 self-reflection 및 개선 데이터로 활용한다. | 셀프 검증 단계 |

### 입력 예시

```text
지난주 대비 A제품 수율 어때?
```

### 기대 출력

```text
A제품의 이번주 수율은 지난주 대비 2.3%p 하락했습니다.

비교 결과:
- 지난주 수율: 96.1%
- 이번주 수율: 93.8%
- 변화폭: -2.3%p

추세 요약:
- 월요일부터 수율 하락이 시작되었습니다.
- 수요일 이후 하락 폭이 가장 크게 나타났습니다.
- 특정 공정 구간에서 불량이 집중되었습니다.

시각화 결과:
- 주간 수율 추세 그래프
- 지난주 vs 이번주 비교 표
- 일별 변동 추이 차트
```

### 성공 기준

- Planner가 사용자 질의를 보고 알맞은 세부 task를 계획한다.
- Supervisor가 Planner 결과를 보고 적절한 sub-agent 조합을 판단한다.
- sub-agent가 기간 비교, 변화량, 추세 요약을 함께 제공한다.
